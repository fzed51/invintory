Authentification

L'inscription et la connexion renvoient un JWT signé en HS256, valable une heure, sans refresh token. Le middleware revérifie à chaque requête que l'utilisateur porté par le token existe toujours en base.

post /auth/register public

Crée un compte et renvoie un JWT.

L'email doit être syntaxiquement valide et le mot de passe faire au moins 8 caractères. Le mot de passe est stocké haché via password_hash. Le token est émis immédiatement : il n'y a pas d'étape de confirmation.

Corps de la requête · application/json

ChampTypeDescription
email requisstring(email)Adresse de connexion, unique.
password requisstring8 caractères minimum.

Réponses

201

Compte créé. Renvoie id, email et token.application/json

400

Email invalide, ou mot de passe trop court.Adresse email invalide. · Le mot de passe doit contenir au moins 8 caractères.

409

Un compte existe déjà pour cet email.Un compte avec cet email existe déjà.

Exemple

$ curl -X POST http://localhost:8080/api/auth/register \
    -H 'Content-Type: application/json' \
    -d '{"email":"caviste@example.test","password":"MotDePasse123"}'

→ 201
{
  "id": 1,
  "email": "caviste@example.test",
  "token": "eyJ0eXAiOiJKV1QiLCJhbGciOiJIUzI1NiJ9..."
}

get /auth/me JWT requis

Renvoie l'identité associée au JWT fourni.

Sert à vérifier qu'un token conservé côté client est toujours valide. Ne renvoie pas de nouveau token.

Réponses

200

Token valide. Renvoie id et email.application/json

401

En-tête absent, token illisible, signature invalide, token expiré, ou utilisateur introuvable en base.Token manquant. · Token invalide ou expiré. · Utilisateur introuvable.

Exemple

$ curl http://localhost:8080/api/auth/me \
    -H "Authorization: Bearer $TOKEN"

→ 200
{ "id": 1, "email": "caviste@example.test" }

Cave

Persistance côté serveur de la cave de l'utilisateur connecté : armoires, bouteilles et cartons. Une cave par compte, stockée comme un document JSON unique.

get /cellar JWT requis

Lit la cave de l'utilisateur connecté.

Renvoie une cave vide — trois tableaux vides et updatedAt: null — lorsque rien n'a encore été enregistré. Cette route ne renvoie jamais 404.

Réponses

200

Cave de l'utilisateur, éventuellement vide.application/json · CellarEnvelope

401

JWT absent ou invalide.Token manquant.

Exemple de réponse

{
  "cellar": {
    "cabinets": [ { "id": "cabinet-1", "name": "Armoire du salon" } ],
    "bottles": [],
    "cartons": []
  },
  "updatedAt": "2026-08-02T10:00:00+00:00"
}
put /cellar JWT requis

Remplace la cave de l'utilisateur connecté.

Écriture intégrale : le contenu envoyé remplace la cave existante, il n'y a pas de fusion. Si updatedAt est absent ou vide, le serveur y met l'heure UTC courante.

Corps de la requête · application/json

ChampTypeDescription
cellar requisCellarDoit contenir cabinets, bottles et cartons.
updatedAtstringHorodatage du client. Remplacé par l'heure UTC si absent.
Le serveur ne valide pas le détail. Seules les trois clés cabinets, bottles et cartons sont retenues, et uniquement vérifiées comme étant des tableaux. Le contenu des éléments est stocké tel quel : la forme documentée dans les schémas est celle que produit l'application front, pas un contrat imposé par l'API.

Réponses

200

Cave enregistrée. Renvoie l'updatedAt retenu par le serveur.application/json

400

Corps JSON illisible, champ cellar absent ou non sérialisable.Corps JSON invalide. · Le champ cellar est requis.

401

JWT absent ou invalide.Token manquant.

Illustrations

Photos de bouteilles et de cartons. Les fichiers ne sont jamais exposés en accès statique public : toute lecture passe par une route authentifiée.

post /images/temp JWT requis

Envoie une illustration et la stocke temporairement.

L'image reçue est normalisée par GD2 en 512 × 1024 JPEG qualité 85 : mise à l'échelle sur la hauteur, puis bandes noires latérales si elle est trop étroite, ou recadrage centré horizontalement si elle est trop large. Le résultat est marqué temporaire et ne devient définitif qu'à la première lecture réussie.

Corps de la requête · multipart/form-data

ChampTypeDescription
image requis fichier 8 000 000 octets maximum. Types acceptés : image/jpeg, image/png, image/webp, image/heic, image/heif.
HEIC et HEIF sont acceptés au contrôle de type mais échouent au traitement — GD ne sait pas les décoder. Ils ressortent en 400 avec « Impossible de traiter l'image fournie ».

Réponses

201

Illustration acceptée et normalisée. Renvoie id, temporary: true et url.application/json

400

Champ absent, fichier vide ou trop volumineux, type non supporté, ou échec du traitement GD.Image manquante. · Image invalide ou trop volumineuse. · Format d'image non supporté.

401

JWT absent ou invalide.Token manquant.

Exemple

$ curl -X POST http://localhost:8080/api/images/temp \
    -H "Authorization: Bearer $TOKEN" \
    -F "image=@bouteille.jpg;type=image/jpeg"

→ 201
{
  "id": "0a0cbd1898708db389f3ad8e11ec91b6",
  "temporary": true,
  "url": "/api/images/0a0cbd1898708db389f3ad8e11ec91b6"
}
get /images/{imageId} JWT requis

Lit une illustration et la rend définitive.

Route passe-plat. Un utilisateur ne peut lire que ses propres illustrations : l'image d'un autre compte renvoie 404, pas 403.

Paramètre de chemin

NomTypeDescription
imageId requisstring32 caractères hexadécimaux minuscules, renvoyés par l'upload.
Effet de bord à connaître. Si l'illustration est encore temporaire, ce premier accès la promeut en définitive et, dans la même transaction, supprime toutes les autres illustrations temporaires du même utilisateur. C'est le mécanisme de nettoyage des images envoyées puis abandonnées sans validation du formulaire.

Réponses

200

Flux binaire de l'illustration, avec Content-Length et Cache-Control: private, max-age=3600.image/jpeg

401

JWT absent ou invalide.Token manquant.

404

Identifiant malformé, inexistant, ou appartenant à un autre utilisateur.Illustration introuvable.

500

Échec de la promotion de l'illustration en définitive.Impossible de finaliser l'illustration.

Error

Toutes les erreurs de l'API partagent cette forme, avec un message en français destiné à l'affichage.

{ "error": "Token invalide ou expiré." }

JWT

Signé en HS256 avec le secret JWT_SECRET, qui doit faire au moins 256 bits (32 octets). Durée de vie une heure.

ClaimTypeDescription
substringIdentifiant utilisateur, sous forme de chaîne.
emailstringAdresse du compte.
iatnumberÉmission, horodatage à la microseconde.
nbfnumberPas avant. Égal à iat, exigé par la validation stricte.
expnumberExpiration, iat + 3600 s.
